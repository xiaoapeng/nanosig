# nanosig v1 共识计划

状态：P0/PD 收口完成，准备进入 P1a。  
更新时间：2026-05-16。

## 目标

nanosig 是一个全新的 C11 signal/slot 库。它借鉴 `tmp/eventhub_os` 的代码风格和部分基础设施思想，但不追求 `eh_*` 源码兼容。v1 的目标交付物是：

- Linux + Windows 可构建、可测试的 C11 库；
- 一个线程最多绑定一个 `ns_loop_t`；
- signal emit 可跨线程进入目标 loop；
- 固定容量 MPSC 队列；
- 全局 timer 服务；
- ASAN/TSAN/UBSAN/AppVerifier 方向的验证入口；
- 三个验收 demo：同线程 signal、跨线程 signal、timer 跨线程触发。

## 已锁定公开 API 决策

### 线程与 loop

- 公开类型名保持 `ns_loop_t`。
- 一个线程最多绑定一个 loop。
- `ns_loop_create` 创建并绑定当前线程的 loop。
- 同一线程重复创建 loop 返回 `NS_E_EXISTS`。
- `ns_loop_current` 返回当前线程绑定的 loop；未绑定时返回 `NS_E_NO_LOOP`。
- 当前线程查找使用平台 TLS fast path；跨线程诊断、重复创建检查和未来按线程句柄查找需求由内部 loop manager 注册表负责。

### signal / slot

- 公开操作统一使用 `ns_signal_*` 前缀。
- 函数包装宏使用小写，例如：
  - `ns_signal_connect_typed`
  - `ns_signal_connect_typed_to`
  - `ns_signal_emit`
  - `ns_signal_init`
- 声明、定义、初始化器、类型检查宏保持大写，例如：
  - `NS_SIGNAL_DEFINE`
  - `NS_SIGNAL_DECLARE`
  - `NS_SIGNAL_INITIALIZER`
  - `NS_DEFINE_SLOT`
  - `NS_SLOT_TYPECHECK`
- `ns_signal_connect_typed` 默认使用当前线程 loop。
- `ns_signal_connect_typed_to` 显式指定目标 loop。
- 底层连接函数只有一个：
  - `ns_signal_connect(signal, slot_fn, target_loop, user_data, out_connection)`
- `target_loop == NULL` 表示使用当前线程 loop；非 `NULL` 表示显式目标 loop。
- 只因“默认参数 / 显式参数”不同而拆分底层函数是零容忍。
- typed connect 在 C11 下使用 `_Generic` 做编译期 slot 签名检查。
- raw connect / raw emit 是给实现层、绑定层、适配层使用的逃生通道。

### payload 与 no-payload

- signal 的 payload 大小由公开宏在编译期烘焙。
- 普通 payload 使用显式结构体类型。
- no-payload 使用 `ns_no_payload_t` 作为类型标记。
- `ns_no_payload_t` 不是可拷贝 payload 对象。
- `NS_NO_PAYLOAD` 是唯一的 no-payload emit 入参。
- `NS_SIGNAL_PAYLOAD_SIZE(ns_no_payload_t)` 必须为 0。
- `NS_SIGNAL_PAYLOAD_PTR_SIZE(NS_NO_PAYLOAD)` 必须为 0。
- no-payload emit / timer 路径必须拷贝 0 字节。
- 不使用 `reserved[0]` 或其他零长数组技巧。

### signal 生命周期

- `ns_signal_t` 可以静态定义，也可以作为用户结构体成员。
- 独立静态对象使用 `NS_SIGNAL_DEFINE(name, payload_type)`。
- 结构体成员使用 `NS_SIGNAL_INITIALIZER(payload_type)`。
- 动态对象使用 `ns_signal_init(signal, payload_type)`。
- 不提供 `ns_signal_deinit`。
- signal 初始化只写元数据；连接资源由 `ns_signal_disconnect` 释放。
- `ns_signal_disconnect_all` 可以作为 teardown / 逃生通道存在，但健康程序通常应保存连接句柄并逐个 `ns_signal_disconnect`。
- disconnect 不取消已经入队的 slot 调用；`user_data` 生命周期必须长于任何 in-flight emit。

### timer

- `ns_timer_t` 是调用方自持存储，不是不透明分配句柄。
- `ns_timer_t` 的第一个字段必须是：

```c
ns_signal_t signal;
```

- timer 到期时触发这个内嵌 no-payload signal。
- timer 只支持无参数触发。
- 创建接口为：

```c
int ns_timer_create(ns_timer_t *timer, ns_time_us_t interval_us, uint32_t attr);
```

- `ns_time_us_t` 是 `uint64_t` 微秒。
- `attr` 是位图：
  - bit0：`NS_TIMER_ATTR_REPEAT`，是否重复；
  - bit1：`NS_TIMER_ATTR_RELOAD_FROM_NOW`，重复重装载时以当前时间为基准，否则优先使用上一次 deadline 步进。
- bit1 未设置时，下一次 deadline 优先为 `previous_deadline + interval_us`；如果该时间已经落后于当前时间，则退化为 `now + interval_us`。
- `ns_timer_cancel` 对任何成功 `ns_timer_create` 的 timer 都合法；未运行时返回成功且无副作用。

### v1 safety 策略

- v1 公开头文件不暴露 `__safety` 注解。
- `include/nanosig/nanosig_safety.h` 仅保留未来 v2 ISR / safety 扩展点。
- emit 路径保持零运行时分配，这是 v2 ISR 能力的前置架构约束。

## 示例与反初始化规则

所有获取多个 nanosig 资源的示例必须使用内核风格 `goto` 清理标签。原则是：

- 每个成功初始化的资源都有对应清理路径；
- create 失败不清理未创建对象；
- timer create 成功后可以直接在清理路径调用 `ns_timer_cancel`，无需 `timer_started` 标志；
- timer create 成功后 `ns_timer_destroy` 必须可达；
- connection 成功后才进入 `ns_signal_disconnect` 清理路径。

## 跨阶段治理

### P3 -> P1 修订协议

如果 MPSC 实现发现 `platform/port.h` 缺失必要原语，只允许重开 P1 做聚焦补丁：

1. 只修改缺失原语；
2. 两个 OS 的 P1b 自测必须重跑；
3. 同步更新 `platform/README.md` 和 `docs/MPSC_MEMORY_ORDER.md`；
4. 不允许顺手重构无关平台接口。

### PD API delta 协议

如果实现阶段发现公开 API 需要修改：

- 破坏签名、移除公开符号、修改调用方可见字段：重新触发用户审核；
- 不破坏的新增：实现阶段内由 architect 评审；
- 纯内部变更：实现阶段内处理，同步文档即可。
