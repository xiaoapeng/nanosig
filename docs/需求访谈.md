## 访谈结论摘要

nanosig 是一个全新的 C11 signal/slot 库。它参考 `tmp/eventhub_os` 的风格、宏习惯和部分基础设施，但不保持源码级 API 兼容。项目的核心变化是：用线程和每线程 event loop 替代 eventhub_os 的协程调度模型。

v1 面向 Linux + Windows；v2 再考虑 RTOS / 裸机 Cortex-M。v1 必须在公开 API 和内部结构上为 v2 ISR 场景保留空间，但不在公开头文件暴露 `__safety` 注解，不实现 MCU 后端，也不把“中断中发射 signal”作为 v1 目标。

## 项目目标

构建一个可移植的 C11 库：

- signal 可以从任意线程 emit；
- slot 在 connect 时绑定到目标 loop；
- 默认 connect 绑定当前线程 loop；
- 显式 `_to` connect 可指定其他线程的 loop；
- 每个线程最多拥有一个 `ns_loop_t`；
- 跨线程投递通过固定容量 MPSC 队列；
- timer 由后续 `ns_event_broker_t` 内置 timer source 管理 deadline，并通过 timer 内嵌 signal 触发 slot；
- 平台差异集中在 `platform/` 层。

## 当前有效 API 决议

### loop

- 公开类型名为 `ns_loop_t`。
- `ns_loop_create` 创建并绑定当前线程 loop。
- 当前线程已有 loop 时返回 `NS_E_EXISTS`。
- `ns_loop_current` 在未绑定 loop 时返回 `NS_E_NO_LOOP`。
- 平台 TLS 只用于当前线程 fast path；P1b 不暴露平台 thread id / equal / hash。未来如需跨线程诊断或按线程句柄查找，由 core-owned loop manager 注册表另行设计。

### signal / slot

- 当前 API 不使用早期访谈中提到的裸 `void *payload` 作为唯一公开写法。
- 当前 API 使用显式 payload 类型和 typed wrapper：

```c
ns_signal_connect_typed(signal_name, slot_fn, payload_type, user_data, out_connection);
ns_signal_connect_typed_to(signal_name, slot_fn, payload_type, target_loop, user_data, out_connection);
```

- raw 逃生通道为：

```c
ns_signal_connect(signal, slot_fn, target_loop, user_data, out_connection);
ns_signal_emit_raw(signal, payload, payload_size);
```

- `target_loop == NULL` 表示当前线程 loop。
- 不允许新增只靠“默认 loop / 显式 loop”区分的成对底层函数。
- typed connect 使用 C11 `_Generic` 做编译期 slot 签名检查。

### no-payload

- 使用 `ns_no_payload_t` 作为 no-payload 类型标记。
- emit 使用 `NS_NO_PAYLOAD`。
- payload 大小宏对 `ns_no_payload_t` 和 `NS_NO_PAYLOAD` 返回 0。
- no-payload 路径拷贝 0 字节。
- 不使用零长数组或伪 payload 对象。

### timer

- 当前 timer API 已从早期“配置对象 / opaque timer”方向收敛为调用方自持对象。
- `ns_timer_t` 的第一个字段是 `ns_signal_t signal`。
- timer 只发 no-payload signal。
- 创建函数为：

```c
int ns_timer_create(ns_timer_t *timer, ns_time_us_t interval_us, uint32_t attr);
```

- 时间单位为 `uint64_t` 微秒。
- `attr` 是位图：
  - bit0：重复；
  - bit1：重复重装载时是否以当前时间为基准。
- `ns_timer_cancel` 对已创建但未运行的 timer 是 no-op 成功路径。

### safety / ISR

- 早期访谈要求公共 API 带 `__safety` 标注；PD 评审后 v1 改为不暴露公开 `__safety`。
- `nanosig_safety.h` 作为未来扩展点保留。
- v1 的实际约束是：emit 路径不允许运行时分配，为未来 ISR 能力预留结构空间，但当前不提供 `*_from_isr` API，也不承诺 public emit 可在 ISR 中调用。

## 约束

- 语言：C11。
- 构建：CMake。
- 平台：v1 支持 Linux + Windows。
- 平台层：`platform/` 是唯一 OS 耦合点。
- 内存：后续实现中，平台层之外的分配必须走平台封装。
- 队列：跨线程 emit 使用固定容量 MPSC，满队返回错误码，不阻塞、不扩容。
- timer：P6 由 `ns_event_broker_t` 内置 timer source + rbtree 管理，不再采用孤立全局 timer thread。
- 示例：多资源初始化必须使用 `goto` 清理标签。
- 命名：公开函数 `ns_*`，公开类型 `ns_*_t`，常量 / 声明 / 定义 / 初始化器宏 `NS_*`，函数包装宏使用小写 `ns_signal_*`。

## 非目标

- v1 不实现 MCU / RTOS 后端。
- v1 不提供 C++ wrapper。
- v1 不保持 eventhub_os 源码兼容。
- v1 不实现自有 heap。
- v1 不提供协程调度。
- v1 不承诺硬实时或固定延迟 SLO；只提供 bench 结果。
- v1 不预创建空的 `freertos/` 或 `baremetal_cortexm/` 目录，避免“看起来支持但不能跑”的假支持。

## 验收标准

- Linux + Windows CMake 构建通过。
- sanitizer / audit 目标逐阶段接入。
- 跨线程 emit demo 可运行：slot 在 connect 绑定的目标线程 loop 上执行。
- timer 跨线程 demo 可运行：100 ms 级重复 timer 触发另一个 loop 上的 slot。
- 公开 API 有单元测试覆盖 happy path 和边界。
- 固定容量 MPSC 满队返回 `NS_E_QUEUE_FULL`。
- 数据结构包含 list、slist、ringbuf、hashtable、rbtree。

- 当前 P2 阶段额外要求：公开头文件、demo、宏矩阵、平台契约和公开数据结构 compile contract 通过；公开 list/slist/ringbuf/hashtable/rbtree 有 CTest 单元覆盖。

## 已揭示并解决的假设

| 假设 | 挑战 | 最终结论 |
|---|---|---|
| 这是 eventhub_os fork | 项目边界澄清 | 全新项目，只借鉴风格和参考实现 |
| 切线程只是为了多核 | 动机追问 | 多核并行、集成线程化代码、RTOS 迁移便利性共同驱动 |
| MCU ISR demo 是 v1 必交付 | 平台范围冲突 | v1 只做架构预留，v2 实现 |
| C++ 模板更合适 | 语言选择 | 坚持 C11 |
| 自带 heap 更完整 | 内存模型选择 | 使用平台分配封装，不实现 heap |
| mutex + condvar 更简单 | 跨线程机制选择 | 采用固定容量 MPSC + 平台 wakeup |
| 必须兼容 eventhub_os API | 反向挑战 | 只保留风格，不保留签名兼容 |
| slot 必须只有 `void *payload` | PD API 评审 | 当前公开 API 使用显式 payload 类型 + raw 逃生通道 |
| no-payload 需要独立 0 后缀函数族 | API 组合爆炸评审 | 使用 `ns_no_payload_t` 和 `NS_NO_PAYLOAD` 收敛到主 API |
| timer 应该 opaque / config 对象创建 | API 评审 | 调用方自持 `ns_timer_t`，首字段内嵌 signal |
| timer cancel 需要外部 started 标志 | 示例评审 | cancel 对已创建 timer 合法，未运行时 no-op |
| v1 公开头应带 `__safety` | PD safety 评审 | v1 不暴露，保留扩展点 |
| Windows 应一步到位 IOCP | 平台复杂度评审 | P1b 只做 loop 单 wakeup；wait-many / handle waitset 留到 P5b broker |
| 每 loop 内嵌 timer 更简单 | timer 架构评审 | timer 作为 `ns_event_broker_t` 内置事件源，deadline 用 rbtree 管理 |

## 访谈轮次摘要

### 第 1 轮：目标边界

问题：项目是否是 eventhub_os 的改造？为什么要从协程切到线程？

结论：

- nanosig 是新项目；
- eventhub_os 是参考源；
- 线程模型用于多核、现有线程化代码集成、RTOS 迁移。

### 第 2 轮：验收范围

问题：v1 必须交付哪些场景？平台范围是什么？

结论：

- v1 交付 Linux + Windows；
- 跨线程 emit demo 和 timer 跨线程 demo 是核心验收；
- MCU / ISR 是 v2 方向，v1 只预留。

### 第 3 轮：约束细化

问题：语言、内存模型、跨线程机制怎么选？

结论：

- C11；
- 平台分配封装；
- 固定容量 MPSC；
- 平台 wakeup。

### 第 4 轮：反向挑战

问题：是否必须保持 eventhub_os API 兼容？性能是否要硬指标？

结论：

- 不保持 API 兼容；
- 性能只做 bench，不做硬 SLO；
- 数据结构保持完整迁移方向。

### 第 5 轮：架构细化

问题：Windows wakeup、timer、MPSC 满队、slot 签名如何处理？

结论：

- Windows P1b 只使用 auto-reset event + 单 handle 等待；
- timer 后移为 `ns_event_broker_t` 内置事件源；
- MPSC 固定容量、满返错；
- slot 签名在 PD 阶段进一步修订为当前 typed wrapper + raw escape hatch。

### 第 6 轮：简化挑战

问题：timer 是否真要专用线程？是否要预创建 RTOS 空骨架？

结论：

- 不保留孤立全局 timer thread，改为后续 broker-owned timer source；
- 不预创建空后端目录；
- 用 `platform/README.md` 和未来 `platform/port.h` 表达扩展方式。
