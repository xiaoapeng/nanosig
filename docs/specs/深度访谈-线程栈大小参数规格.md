## 目标

让 nanosig 的线程创建支持**运行期可差异化**的栈大小，同时让**库内建线程（broker/timer 线程）的栈大小在编译期锁死**、可由外部通过 CMake 覆盖。

具体：

1. 公共线程创建 API 增加一个 `stack_size` 参数（单位：字节），`0` 表示"用编译期默认值"。
2. `ns_loop_config_t` 增加 `stack_size` 字段，使每个 loop 的后台线程栈可独立配置。
3. **broker（驱动 timer manager）线程**的栈大小由**唯一**宏 `NANOSIG_BROKER_STACK_SIZE` 决定 —— 即"编译期锁死"。配置入口按构建系统各用顺手的那个：CMake 构建用 `-DNANOSIG_BROKER_STACK_SIZE=<bytes>`，Zephyr 构建用 `prj.conf` 的 `CONFIG_NANOSIG_BROKER_STACK_SIZE=<bytes>`。两者转发成**同名**库内宏。
4. 其余线程（用户自建、loop 后台线程）的栈大小由**运行期参数**决定，与 broker 宏无关。
5. **设计红线**：`src/` 与 `include/` 里**不做任何平台判断**、**不引入第二个宏**。后端差异全部收敛在 `platform/*.c`。

## 约束

- **C-1 公共头不得含 OS 预处理器分支**（AGENTS.md）。故公共参数单位必须是可移植单位 → **字节**。
- **C-2 禁止 default-vs-explicit 双函数家族**（AGENTS.md）。只加**一个**参数，不加 `ns_platform_thread_init_ex` 之类。
- **C-3 唯一对外可配宏**：`NANOSIG_BROKER_STACK_SIZE`（字节）。既有 `NANOSIG_FREERTOS_THREAD_STACK_WORDS`（CMakeLists.txt:49-50, 171；platform/freertos/port.c:62-64）与 `CONFIG_NANOSIG_ZEPHYR_THREAD_STACK_SIZE`（zephyr/Kconfig:30-38；platform/zephyr/nanosig_platform_port.h:43-50）**退役**，由新宏取代。
- **C-3b 宏的作用对象只有 broker 线程，且是**库内部**构建旋钮，不进公共头**。定义与强制检查放在 `src/ns_broker.c`（唯一使用者）：`#ifndef NANOSIG_BROKER_STACK_SIZE` → `#error`。构建系统**必须**注入，注入缺失 = 编译失败（不是静默回落 0）。CMake 侧用 `PRIVATE` 编译定义，不外泄给消费者。（`include/nanosig/internal/ns_broker.h` 被 `test/unit/test_broker_lifecycle.c:20` include，故 `#error` 不能放该头。）
- **C-3c `src/` 与 `include/` 不得出现平台判断分支**（AGENTS.md 既有约束，本改动不得违反）。`NANOSIG_BROKER_STACK_SIZE` 是平台无关的普通宏（字节），不含 `CONFIG_*` 之类平台专有符号；Zephyr 的 Kconfig → 宏的转发发生在构建脚本 `zephyr/CMakeLists.txt`，不进公共头。
- **C-4 零行为变化**：默认配置下，五个后端的实际栈大小与改动前逐字节一致。
- **C-5 Zephyr 走运行期动态栈**（用户已选 B 方案）：`k_thread_stack_alloc` + `k_thread_stack_free`，替换内嵌 `K_KERNEL_STACK_MEMBER`。
- **C-6 栈大小越界必须报错**，不静默 clamp 到更小值。
- **C-7 Zephyr 内核配置**：nanosig 的 `zephyr/Kconfig` 需 `select DYNAMIC_THREAD` + `select THREAD_STACK_INFO` + `select DYNAMIC_THREAD_ALLOC`（依据见"技术上下文"）。
- **C-8 阶段编号禁令**：源码/注释/字符串/标识符不得出现 `P0`/`P1`/`PD` 等计划阶段引用。

## 非目标

- **NG-1** 不改 `ns_platform_thread_t` 的所有权模型。Zephyr 后端仍是 port 分配的不透明对象（`k_aligned_alloc` + join 时 `k_free`），不顺带做 caller-owned 重构（另有 `.omc/plans/ns-platform-type-refactor-plan.md` 覆盖）。
- **NG-2** 不给 FreeRTOS / Zephyr 保留独立的栈大小 Kconfig / CMake 旋钮 —— 只有一个宏。
- **NG-3** 不做栈水位监测、栈溢出检测、栈使用统计。
- **NG-4** 不改 broker 线程与 loop 线程的职责划分。
- **NG-5** 不改 `ns_signal_emit_raw` / slot 调用语义。

## 决策

### D-1 公共 API

```c
/* include/nanosig/nanosig_port.h */
int ns_platform_thread_init(
    ns_platform_thread_t *thread,
    ns_platform_thread_fn entry,
    void *arg,
    const char *debug_name,
    size_t stack_size);
```

- `stack_size`：字节。`0` = 使用**平台原生默认**（见 D-3 各后端兜底），**与 broker 宏无关**。
- 这是**破坏性签名变更**：全库 12 处调用点必须同步更新（含 `demos/`、`test/`）。

```c
/* include/nanosig/nanosig_loop.h */
typedef struct ns_loop_config {
    ns_capacity_t queue_byte_capacity;
    uint32_t      flags;
    const char   *debug_name;
    size_t        stack_size;   /* 新增：字节；0 = 平台原生默认 */
} ns_loop_config_t;
```

- `NS_LOOP_CONFIG_DEFAULT()` 两个分支都要补 `.stack_size = 0u`（C++ 分支是位置初始化，需追加 `, 0u`）。
- `ns_loop_start()` 把 `loop->config.stack_size` 传给 `ns_platform_thread_init`（src/nanosig.c:296）。

### D-2 编译期默认宏（唯一，对象 = broker 线程）

```
NANOSIG_BROKER_STACK_SIZE     单位：字节
```

**位置与强制注入**（经共识修订，2026-10-21）：

宏是**库内部构建旋钮**，不进公共头。`src/ns_broker.c`（唯一使用者）内：

```c
#ifndef NANOSIG_BROKER_STACK_SIZE
#error "NANOSIG_BROKER_STACK_SIZE must be injected by the build system \
(CMake cache variable / Zephyr Kconfig)"
#endif
```

- 注入缺失 → **编译失败**，不是静默回落 0。这样"编译期锁死"才是可强制的承诺，而不是名义上的。
- CMake 侧用 `PRIVATE` 编译定义（`target_compile_definitions(nanosig PRIVATE …)`），不外泄给消费者，也不占用公共 API 面。
- `#error` 放 `.c` 而非 `include/nanosig/internal/ns_broker.h` —— 后者被 `test/unit/test_broker_lifecycle.c:20` include，测试目标不继承 `PRIVATE` 定义。

两级语义：

| 层级 | 值 | 含义 |
|---|---|---|
| broker 线程调用点 | 传 `NANOSIG_BROKER_STACK_SIZE` | 宏为 `0` → 平台原生默认；非 0 → 该字节数 |
| 用户线程调用点 | 传 `0` | 平台原生默认（**不读 broker 宏**） |

**配置入口 —— 按构建系统各一个，底层同一个宏、同一个数字：**

```cmake
# 顶层 CMakeLists.txt（host 与 freertos 共用，全平台生效）
set(NANOSIG_BROKER_STACK_SIZE "0" CACHE STRING
    "Broker (timer) thread stack size in bytes (0 = platform default)")
target_compile_definitions(nanosig PRIVATE
    NANOSIG_BROKER_STACK_SIZE=${NANOSIG_BROKER_STACK_SIZE})
```

```cmake
# zephyr/CMakeLists.txt（Zephyr module 构建入口）
# 与既有 zephyr_compile_definitions(NS_MPSC_CACHELINE_ALIGNED) 同一块，
# 位于 zephyr_library() 之前（该写法已被 Zephyr CI 验证有效）。
zephyr_compile_definitions(
    NS_MPSC_CACHELINE_ALIGNED
    NANOSIG_BROKER_STACK_SIZE=${CONFIG_NANOSIG_BROKER_STACK_SIZE}
)
```

```conf
# zephyr/Kconfig
config NANOSIG_BROKER_STACK_SIZE
    int "nanosig broker (timer) thread stack size (bytes)"
    depends on NANOSIG_ZEPHYR
    default 0
    range 0 65536
    help
      Stack size of the nanosig broker (timer) thread, in bytes. 0 means the
      Zephyr backend default (4096). Set in the application's prj.conf.
```

CMake 构建的用户：

```sh
# 默认留 0（= 平台默认）。若必须显式锁死，取值须 >= 目标平台的最小栈，
# 否则 host 上 ns_init() 会直接返回 NS_E_INVAL。
cmake --preset linux-release -DNANOSIG_BROKER_STACK_SIZE=65536
```

Zephyr 应用的用户（`test/zephyr/prj.conf`）：

```
CONFIG_NANOSIG_BROKER_STACK_SIZE=4096
```

默认 `0` = 零行为变化（各后端兜底见 D-3）。嵌入式目标若要**显式锁死**，建议设 `4096`（字节）—— 与现状逐字节一致（FreeRTOS 1024 words @32-bit、Zephyr 4096 字节），但不再依赖"0 → 兜底"的隐式路径。

> `zephyr/Kconfig` 中原 `CONFIG_NANOSIG_ZEPHYR_THREAD_STACK_SIZE` 符号（default 4096 / range 1024..65536）被 `CONFIG_NANOSIG_BROKER_STACK_SIZE` 取代：作用对象相同（broker 线程），但语义收敛到"唯一宏"（0 = 平台默认）。Zephyr 侧的 `prj.conf` 入口**保留**。

### D-2b 平台栈上下限查询

```c
/* include/nanosig/nanosig_port.h */
int ns_platform_thread_stack_range(size_t *min_out, size_t *max_out);
```

- 返回该后端接受的栈大小区间（字节）。`min_out` = 后端下限（POSIX 为 `PTHREAD_STACK_MIN`；Windows / Zephyr 为 nanosig 策略下限；FreeRTOS 为 `configMINIMAL_STACK_SIZE` 对应字节数）。`max_out` = 后端上限（`SIZE_MAX` 表示无实际上限；Windows 为 `UINT_MAX`）。
- 作用：① 让"下界"成为**可发现**的契约而不是藏在实现里的魔数；② 让"过小 → `NS_E_INVAL`"这条判据可以在**所有后端用同一份测试**表达（`min - 1`）；③ 用户要把线程栈调小（省 RAM）时需要知道合法下界。
- 这**不是** default-vs-explicit 双函数家族，不违反 AGENTS.md；它是一个查询函数，不增加配置面。

### D-3 各后端映射

| 后端 | `stack_size == 0` 的兜底 | 非 0 时怎么做 | 最小值检查 |
|---|---|---|---|
| Linux | OS 默认（`pthread_create` 传 `NULL` attr；glibc 8 MB） | `pthread_attr_init` → `pthread_attr_setstacksize` → `pthread_attr_destroy`；请求先**向上取整到页粒度 4096**（Darwin 要求请求是页大小的整数倍，否则直接 EINVAL，不代为取整） | `< PTHREAD_STACK_MIN` → `NS_E_INVAL` |
| macOS | OS 默认（`NULL` attr；Darwin 512 KB） | 同上 | 同上 |
| Windows | OS 默认（`_beginthreadex(..., 0u, ...)`；1 MB） | 直接作为 `_beginthreadex` 第 2 参 | 低于 Win32 实用最小值 → `NS_E_INVAL`（实现时按 MSDN 复核具体常量） |
| FreeRTOS | **2 KB（2048 字节）** | `words = ceil(bytes / sizeof(StackType_t))`，**向上取整**保证实际字节数 ≥ 请求值 | 低于 nanosig 策略值 **1024 字节**（换算成 words 后比较）→ `NS_E_INVAL`。**不沿用 `configMINIMAL_STACK_SIZE`**（那是 FreeRTOS 给 idle 任务的惯例深度，`xTaskCreate` 并不强制） |
| Zephyr | **2048 字节** | `k_thread_stack_alloc(bytes, 0)` → `k_thread_create` | 低于 nanosig 自定下限 → `NS_E_INVAL`（**Zephyr 3.7 无 `Z_MIN_THREAD_STACK_SIZE`，`k_thread_stack_alloc` 自身不做任何下限检查** —— 太小会被静默分配然后运行时溢栈，故下限必须由后端自己把关） |

兜底常量（FreeRTOS / Zephyr 各 2 KB）是**后端内部常量，不是配置面**；对外可配的宏仍然只有 `NANOSIG_BROKER_STACK_SIZE` 一个，且只作用于 broker 线程。

> **嵌入式 2 KB 的取舍（作者决定）**：该值小于 FreeRTOS 惯例的 idle 任务栈（`configMINIMAL_STACK_SIZE` = 1024 words），而 broker 线程还要执行用户的 `watcher->handler`。这是明确的省 RAM 取舍，由 `configCHECK_FOR_STACK_OVERFLOW` 与调用方自行评估 handler 深度兜底。

### D-4 Zephyr 走动态栈（B 方案）

```c
/* platform/zephyr/port.c */
struct ns_platform_thread {
    struct k_thread        thread;
    ns_platform_thread_fn  entry;
    void                  *arg;
    k_thread_stack_t      *stack;   /* 新增：动态分配的栈 */
};
```

- `ns_platform_thread_init`：`k_thread_stack_alloc(stack_bytes, 0)` → 失败返回 `NS_E_NOMEM` → `k_thread_create(&obj->thread, obj->stack, stack_bytes, ...)`。
- `ns_platform_thread_join`：`k_thread_join` → `k_thread_stack_free(obj->stack)` → 释放对象。
- 对象不再内嵌内核栈 → **不再需要 `Z_KERNEL_STACK_OBJ_ALIGN` 对齐**（该约束来自内嵌栈，见 platform/zephyr/port.c:238-245 注释）。对象分配可退化为普通分配。
- 现有 `k_thread_create` 返回值被 `(void)` 丢弃（platform/zephyr/port.c:279）——本改动顺带修掉：创建失败必须返回错误码，不得报 `NS_OK`。
- `zephyr/Kconfig` 新增：

```
config NANOSIG_ZEPHYR
    ...
    select DYNAMIC_THREAD
    select THREAD_STACK_INFO
    select DYNAMIC_THREAD_ALLOC
```

依据（Zephyr v3.7.0 源码已核）：

- `include/zephyr/kernel.h:268` — `k_thread_stack_alloc()` 注释明写 `@see CONFIG_DYNAMIC_THREAD`。
- `kernel/Kconfig:235` — `config DYNAMIC_THREAD`，标题 "Support for dynamic threads [EXPERIMENTAL]"，`select EXPERIMENTAL`、`depends on THREAD_STACK_INFO`、`select THREAD_MONITOR`。
- `depends on THREAD_STACK_INFO` 且 `THREAD_STACK_INFO` 默认 n → 只 `select DYNAMIC_THREAD` 会 unmet dependency，故必须一并 select。
- `kernel/dynamic.c:81-101` — `CONFIG_DYNAMIC_THREAD_PREFER_POOL`（默认）+ `CONFIG_DYNAMIC_THREAD_POOL_SIZE=0`（默认，池空）+ `CONFIG_DYNAMIC_THREAD_ALLOC` 未开 → `k_thread_stack_alloc` **返回 NULL**。故必须 select `DYNAMIC_THREAD_ALLOC`。

### D-6 文档同步

- `platform/README.md`、`docs/agents/platform/AGENTS.md`、`docs/ARCHITECTURE.md`（平台能力表）、`docs/BROKER_DESIGN.md`（`ns_platform_thread_init / join` 一节）：补 `stack_size` 语义与各后端映射。

## 验收标准

### 公共 API

- [ ] **AC-1** `ns_platform_thread_init` 接受第 5 个参数 `size_t stack_size`；`stack_size == 0` 时走**改动前的代码路径原样**（POSIX 传 `NULL` attr、Windows 传 `0u`、FreeRTOS 1024 words、Zephyr 4096 字节）—— 判据是"该分支与改动前逐行等价"，而非"实际字节数可观测"（OS 默认栈大小在进程内不可读）。
- [ ] **AC-1b** 新增 `ns_platform_thread_stack_range(size_t *min_out, size_t *max_out)`：五个后端各返回一个有效区间；`min_out - 1` 在所有后端都被拒绝（`NS_E_INVAL`），`min_out` 被接受。
- [ ] **AC-2** `ns_loop_config_t` 含 `stack_size`；`NS_LOOP_CONFIG_DEFAULT()` 在 C 与 C++ 两个分支下均返回 `stack_size == 0`（C++ 分支由 `test/unit/test_cpp_compat_compile.cpp` 断言）。
- [ ] **AC-3** `ns_loop_start()` 使用 `loop->config.stack_size` 创建后台线程；`ns_loop_config_t` 为 `NULL`（走 `NS_LOOP_CONFIG_DEFAULT()`）时行为与改动前一致。

### 后端

- [ ] **AC-4** Linux / macOS：`stack_size != 0` 时通过 `pthread_attr_setstacksize` 生效（请求先向上取整到页粒度 4096，实际栈 ≥ 请求值）；`stack_size < PTHREAD_STACK_MIN` 返回 `NS_E_INVAL` 且不创建线程。
- [ ] **AC-5** Windows：`stack_size != 0` 时作为 `_beginthreadex` 第 2 参生效；过小值返回 `NS_E_INVAL`。
- [ ] **AC-6** FreeRTOS：`stack_size`（字节）按 `sizeof(StackType_t)` **向上取整**换算为 words，实际栈字节数 ≥ 请求值；换算后 words 低于 nanosig 策略下限（1024 字节换算值）返回 `NS_E_INVAL`。默认值 2 KB。
- [ ] **AC-7** Zephyr：`stack_size != 0` 时由 `k_thread_stack_alloc` 分配该字节数的栈，`join` 后 `k_thread_stack_free` 释放；低于后端策略下界（512 B）返回 `NS_E_INVAL`；默认值 2048 字节。（`k_thread_create` 返回的是 `k_tid_t` 指针而非错误码，按 NULL 判定；Zephyr 3.7 无 `Z_MIN_THREAD_STACK_SIZE`，下限由 nanosig 自定。）
- [ ] **AC-8** Zephyr：`k_thread_create` 失败时 `ns_platform_thread_init` 返回错误码（不再是 `NS_OK`）。

## 宏清单（本次改动涉及的全部编译期宏）

### A. 对外可配（用户需传入，1 个宏 / 2 个入口）

| 宏 / 符号 | 单位 | 设置位置 | 默认 | 作用对象 |
|---|---|---|---|---|
| `NANOSIG_BROKER_STACK_SIZE` | 字节 | 顶层 `CMakeLists.txt` 的同名 cache 变量 | `0` = 平台原生默认 | **仅 broker（timer）线程** |
| `CONFIG_NANOSIG_BROKER_STACK_SIZE` | 字节 | Zephyr 应用的 `prj.conf` | `0` = 平台原生默认 | 同上（转发成同名库内宏） |

嵌入式目标若要**显式锁死**，建议设 `4096`（字节）—— 与现状逐字节一致（FreeRTOS 1024 words @32-bit、Zephyr 4096 字节），但不再依赖"0 → 兜底"的隐式路径。

**库内只有 `NANOSIG_BROKER_STACK_SIZE` 一个宏**，且是**内部旋钮**（定义与 `#error` 强制注入检查都在 `src/ns_broker.c`，不进公共头、CMake 用 `PRIVATE`）；`CONFIG_NANOSIG_BROKER_STACK_SIZE` 是 Zephyr 构建期的 Kconfig 符号，只在 `zephyr/CMakeLists.txt` 里被转发成前者，不进 `include/`、不进 `src/`。

> **单位迁移提示**：`NANOSIG_FREERTOS_THREAD_STACK_WORDS`（words，且作用于**所有**平台线程）被字节制、仅作用于 broker 的新宏取代。FreeRTOS 上 `sizeof(StackType_t)` 在目标板通常是 4、在 64 位 POSIX harness 上通常是 8 → 旧的 1024 words = 4096 B @32-bit、8192 B @64-bit。迁移文档须写明。

## 暴露并解决的假设

| 假设 | 质疑方式 | 结论 |
|---|---|---|
| "代码里有定时器线程" | 查 `ns_timer_mgr_fire_expired` 与 `ns_broker_run` | 无独立 timer 线程；timer manager 由 broker 线程被动驱动。所谓"定时器线程"= broker 线程 |
| "broker 线程不跑用户回调" | 用户直接反驳；复查 `grep "handler(" src/` | **我错了**。src/ns_broker.c:339 `watcher->handler(...)` 直接在 broker 线程执行用户回调。timer slot 回调才在 loop 线程（唯一调用点 src/nanosig.c:210） |
| "Zephyr 不能运行期 malloc" | 用户反问；核 platform/zephyr/port.c | 错。后端**已经**用 `k_aligned_alloc`/`k_free`（:270, :290）。真约束是内嵌栈维度编译期固定 + `k_thread_stack_alloc` 被 `CONFIG_DYNAMIC_THREAD` 门控 |
| "Zephyr 动态栈需要 `CONFIG_DYNAMIC_THREAD`" | 拉 Zephyr v3.7.0 源码核对 | 成立，且额外需要 `THREAD_STACK_INFO`（依赖）与 `DYNAMIC_THREAD_ALLOC`（否则 alloc 返回 NULL） |
| "一个宏就够" | 用户指令 | 成立。统一为 `NANOSIG_BROKER_STACK_SIZE`（字节），退役 FreeRTOS / Zephyr 两个旧旋钮 |
| "一个宏管所有线程的默认栈" | 用户反问 "应该强调是 br 的线程吧" | **错**。宏改为只作用于 broker 线程；用户线程传 0 = 平台原生默认，与宏无关。宏因此必须定义在 `nanosig_port.h`（`src/ns_broker.c` 可见）并由 broker 显式传入 |
| "Zephyr 只能走 CMake 入口" | 用户反问 "prj 干嘛用的…至于入口，我觉得 prj 也可以啊" | **错**。`prj.conf` 是 Zephyr 应用的 Kconfig 配置片段，nanosig 作为 module 在 `zephyr/Kconfig` 提供符号、应用在 `prj.conf` 赋值。Zephyr 侧保留 prj.conf 入口，由 `zephyr/CMakeLists.txt` 转发成同名库内宏（不进公共头，故 `include/`/`src/` 仍无平台判断） |
| "锁死值要重新选" | 估算 broker 内部栈（~800 B ~ 1.2 KB @32-bit）+ 用户 handler 预算 | 不改。保留现值（FreeRTOS 1024 words / Zephyr 4096 B）—— 唯一有出货背书的数字；省 RAM 的收益来自**用户线程差异化**，不是压 broker 线程 |

## 本体（关键实体）

| 实体 | 类型 | 字段 | 关系 |
|---|---|---|---|
| `stack_size`（公共参数） | 核心域 | 字节数，0 = 平台原生默认 | 被 `ns_platform_thread_init` 消费；被 `ns_loop_config_t.stack_size` 驱动 |
| `NANOSIG_BROKER_STACK_SIZE` | 核心域 | 字节数，0 = 平台默认 | **仅**决定 broker 线程的栈大小；CMake 注入；定义在 `nanosig_port.h` |
| broker 线程 | 核心域 | `ns_platform_thread_t` | 驱动 timer manager；**执行 watcher handler**；栈 = `NANOSIG_BROKER_STACK_SIZE`（编译期锁死） |
| loop 线程 | 核心域 | `ns_platform_thread_t` | 由 `ns_loop_start` 创建；**执行 timer slot 回调**；栈 = `ns_loop_config_t.stack_size` |
| 平台后端 | 外部系统 | Linux / macOS / Windows / FreeRTOS / Zephyr | 各自把字节数映射到原生原语；单位换算与下限检查归各自后端 |
