## Goal

产出两层测试代码，覆盖 nanosig 的信号槽 (signal/slot)、timer、broker 三个组件在各个测试维度（功能正确性、并发安全、边界条件、错误处理、长时间稳定性、内存安全、跨平台兼容）上的验证：

1. **补全单元测试** (`test/unit/`)：填补 P9 审计列出的 Critical + Major 级别测试缺口
2. **复杂集成测试** (`test/integration/`)：15 个独立的自验证 demo，模拟真实复杂业务场景，组合使用信号槽/Timer/Broker，覆盖从长稳到极端并发的全面验证

## Constraints

### 位置与命名
- 单元测试：`test/unit/test_signal.c` / `test_timer.c` / `test_broker.c`（已有，新增用例）
- 集成测试：新建 `test/integration/` 目录，每个场景一个 `.c` 文件
- 集成测试 CMake 目标命名模式：`nanosig_test_integration_{slug}`
- 集成测试注册到 CTest，可 `ctest -R integration` 单独运行

### 测试质量约束
- **自动验证**：每个用例必须有 assert / 错误码检查，非 0 退出视为失败
- **全周期内存检查**：所有测试在 ASAN (AddressSanitizer) 下通过；集成测试额外验证 LSAN (LeakSanitizer) 无泄漏
- **完美退出**：每个测试结束后所有线程已 join、所有 mutex 已销毁、所有信号已 deinit、loop 已 destroy、`ns_shutdown()` 返回 OK
- **演示性**：集成测试运行时打印阶段标记（`[PHASE]`、`[PASS]`、`[STATS]`），人可以直接观察执行进度和结果

### 技术与环境约束
- **资源消耗**：不包含资源饥饿/耗尽测试，不对宿主机器产生负面影响
- **MPSC ring 容量**：每个集成测试场景必须明确标注 `queue_byte_capacity` 需求。高并发场景（群蜂归巢、定时器风暴、信号风暴）必须使用足够大的容量（`NS_CAPACITY_65536` 及以上），防止 `E_QUEUE_FULL` 丢信号
- **跨平台**：测试代码必须兼容 macOS / Linux / Windows 三平台（已有 `#ifdef _WIN32` / `__APPLE__` 模式可复用）
- **运行时长**：长时间场景（群蜂归巢 20min）在 CTest 中标注 `TIMEOUT` 属性

### 排除范围（Non-Goals）
- 不包含环形缓冲区、list、hashtable、rbtree、slist 等数据结构的单独测试（已有 P2 测试覆盖）
- 不包含 resource starvation / memory pressure 测试
- 不包含 ISR-safe 路径测试（v2 课题）

## Acceptance Criteria

### 单元测试补全（P9 审计缺口）

**Critical — 核心不变量（必须覆盖）：**
- [ ] `test_signal_disconnect_does_not_cancel_enqueued`: emit → 另一线程 dispatch 中 → 主线程 disconnect → 验证已入队 slot 仍执行
- [ ] `test_broker_error_continue`: 模拟 waittest_wait 失败路径，验证 broker 线程 continue 而非崩溃
- [ ] `test_timer_attr_reload_from_now`: 验证 bit1 设置的 deadline 行为

**Major — 边界/负面/错误码（必须覆盖）：**
- [ ] `test_signal_emit_wrong_payload_size`: emit_raw 大小不匹配返回错误
- [ ] `test_signal_connect_null_loop`: target_loop=NULL → 返回 E_INVAL
- [ ] `test_signal_deinit_with_connections`: deinit 时还有连接，验证行为
- [ ] `test_loop_multi_simultaneous`: 2 loop + 2 thread run + cross-emit
- [ ] `test_loop_queue_overflow`: emit > loop ring capacity
- [ ] `test_watcher_deinit_before_remove`: 先 deinit → 后 remove 返回
- [ ] `test_broker_add_invalid_fd`: 无效 fd 后 destroy
- [ ] `test_repeat_timer_multiple`: 短时间内多次 fire
- [ ] `test_async_cross_thread`: 另一线程 start/stop
- [ ] `test_broker_remove_does_not_cancel_enqueued`: 类似 disconnect 验证
- [ ] `test_repeat_timer_reload_from_now`: bit1 类型 timer (已在 Critical 中)

**Minor（建议覆盖）：**
- [ ] edge_triggered vs level_triggered 差异测试
- [ ] `NS_WAITABLE_EVENT_OUT/ERR` 事件触发测试
- [ ] timer 极短间隔（1μs）
- [ ] signal 作为 struct 成员 + 跨线程 emit 运行时测试
- [ ] 测试框架增强：expect 宏增加行号堆栈上下文

### 集成测试（15 个场景）

**Layer 1 — 基础复杂组合：**
- [ ] **群蜂归巢**: 20 fd watcher + 200 随机定时器（1ms-5s）+ 运行 20 分钟。容量需求: `NS_CAPACITY_65536`
- [ ] **级联信号链**: Timer cascade（线性链 depth 10 + 分支链），验证因果链不丢失。容量需求: `NS_CAPACITY_16384`
- [ ] **看门狗模式**: 定时器周期性检查 watcher 活动，异常时 auto-remove。容量需求: `NS_CAPACITY_8192`
- [ ] **双 Loop 桥接**: Loop-1 IO → emit → Loop-2 计算处理。容量需求: `NS_CAPACITY_16384`
- [ ] **生命周期混战**: 运行时随机 add/remove/disconnect/reconnect watcher+timer。容量需求: `NS_CAPACITY_32768`

**Layer 2 — 压力测试：**
- [ ] **定时器风暴**: 数千个短周期 timer（100μs-1ms）并发启动。容量需求: `NS_CAPACITY_262144`
- [ ] **混沌测试**: 随机组合 emit + disconnect + add + remove + cancel + restart。容量需求: `NS_CAPACITY_65536`
- [ ] **信号风暴**: 1 signal → 50 slot + 1000 次并发 emit。容量需求: `NS_CAPACITY_262144`
- [ ] **重入竞态**: slot 回调内调用 broker_add/remove/timer_start/cancel + 8 线程同时 emit。容量需求: `NS_CAPACITY_65536`

**Layer 3 — 行为验证：**
- [ ] **多 Loop 路由拓扑**: 3 loop + fan-in/fan-out + 交叉连接，验证路由正确性。容量需求: `NS_CAPACITY_32768`
- [ ] **定时器精度与过载**: 多种间隔（100μs-1s）repeat timer + 超长 handler（5ms），验证不追赶 + 精度统计。容量需求: `NS_CAPACITY_16384`
- [ ] **鸡尾酒派对**: 多种 payload 类型混跑（no-payload/int/small struct/large struct），验证内存安全。容量需求: `NS_CAPACITY_32768`
- [ ] **空转无泄漏**: 0 watcher + 0 timer，空转 30s，验证线程正确休眠、零活动无泄漏。容量需求: `NS_CAPACITY_1024`（默认）
- [ ] **多 phase 生命长跑**: init → phase-1(timer) → phase-2(+watcher) → phase-3(mixed) → phase-4(shutdown) → re-init → 再跑，重复 3 轮。容量需求: `NS_CAPACITY_16384`
- [ ] **资源清理验证**: 跨场景强制 handle/thread/mutex 计数归零检查，所有集成测试共享此兜底验证。容量需求: `NS_CAPACITY_1024`

### 跨场景全局条件
- [ ] 每个测试在 CI 中 `ctest -R integration --timeout 1800` 可批量运行
- [ ] 每个测试在 ASAN enabled 构建下零错误
- [ ] 长稳测试（群蜂归巢）标注 CTest `TIMEOUT 1500`
- [ ] CTest 支持筛选项：`ctest -R unit`、`ctest -R integration`、`ctest -R "integration-(hive|chaos|storm)"`

## Technical Context

### 代码库现状
- **已有测试框架**: 无第三方框架，手写 `EXPECT_OK` / `EXPECT_EQ` 宏，`main()` 串行调用测试函数
- **已有测试文件**:
  - `test/unit/test_signal.c` — 711 行，10 个测试
  - `test/unit/test_timer.c` — 207 行，5 个测试
  - `test/unit/test_broker.c` — 460 行，6 个测试
  - `test/unit/test_helpers.h` — 平台相关 waitable helper 函数
- **P9 审计产出**: `docs/audit/behavior_contract_audit.md` 详细列出了测试缺口矩阵
- **demos/**: 3 个验收 demo（demo_same_thread / cross_thread / timer_cross_thread）

### 关键技术细节
- **loop 配置**: `ns_loop_config_t.queue_byte_capacity` 控制 MPSC ring 字节容量，默认 `NS_CAPACITY_1024`
- **emit 记录大小**: 每次 emit ≈ `sizeof(ns_slot_call_t)`（24 bytes）+ payload + alignment
- **可用容量枚举**: `NS_CAPACITY_1024` ~ `NS_CAPACITY_1073741824`（2^n 枚举，`include/nanosig/nanosig_types.h`）
- **集成测试 CMake 注册模式**: `nanosig_add_unit_test(nanosig_test_integration_hive test/integration/test_integration_hive.c)`
- **CTest TIMEOUT**: 长时测试需通过 `set_tests_properties` 设置
