## 1. Requirements Summary

在不引入 OS/RTOS、不使用堆、不使用线程的前提下，让 nanosig 的 **signal/slot** 与 **timer** 两个子系统在裸机 MCU 上工作。三条硬约束：

1. **异步派发语义保留** —— `ns_signal_emit()` 只入队，回调在 `ns_loop_poll()` 中派发（spec Round 4 Contrarian 明确否决了同步直调方案）。
2. **裸机后端只有 3 个 `ns_platform_*` 符号** —— `init` / `shutdown` / `clock_monotonic_us`。
3. **零堆、零线程、零 ISR 依赖**。

范围外：`ns_watcher_*`、`ns_broker_*`、waitset/event/thread 功能；ISR 上下文 emit；多 loop 实例。

## 2. RALPLAN-DR Summary

### Principles

- **P1 单一能力宏（精确表述）**：裸机判定只有 `NANOSIG_BAREMETAL` 一个宏，由 `platform/baremetal/nanosig_platform_port.h` 定义。它在 `include/nanosig/` 中**仅允许**作为 `nanosig_signal.h` 的成员声明守卫；此外 `src/` 与 `include/nanosig/` 中不得出现任何其他裸机判定宏，也不得出现任何 **OS 身份宏**（`_WIN32`/`__linux__`/`__APPLE__`/`FreeRTOS`/`Zephyr`）。
- **P2 能力缺失不得伪装**：分配器、线程、waitset、event、broker **不产生符号**，引用即链接期失败；mutex/wakeup 因单执行上下文而**整体消失**（符号与成员都不复存在）。硬规则：`nm` 中不得存在任何 `ns_platform_*` 的**未经 spec 授权的空实现**（`init`/`shutdown` 为空实现是 spec:45 明确许可的例外）。
- **P3 语义不加平台分叉**：`ns_signal_*` / `ns_timer_*` / `ns_loop_destroy` 在所有后端语义一致。裸机不得发明 host 没有的错误码（例如 `destroy` 遇到非空 ring 返回 `NS_E_BUSY` —— 已否决）。`ns_signal_lock/unlock` 裸机版**保留** `!mutex_initialized → NS_E_INVAL` 守卫（`src/nanosig.c:58/:64`）。
- **P4 零回归优先**：桌面三后端与 FreeRTOS/Zephyr 的既有行为、`ctest`、`api-compile-checks` 全绿。
- **P5 平台层仍是唯一 OS 耦合点**：类型与时钟注入点都在 `platform/baremetal/` 构建内头。

### Decision Drivers

- **D1 机器可验证**：每条能力边界用 `nm`（含 macOS `_` 前缀处理）或链接失败断言，并带 `-Werror` 的裸机 preset。
- **D2 与既有 5 后端同构**：复用「新增后端清单」，不适用项以「能力子集后端」条款显式替代。
- **D3 可测试性**：host harness + 假时钟 + `ctest`，四个构建目录。

### Viable Options

#### Option A′（选定）: 成员级 `#ifdef` + 哑类型（仅用于声明）
后端头提供 `ns_platform_{mutex,wakeup,thread,waitset}_t` 的哑完整类型（`nanosig_port.h:243-604` 的函数声明需要），但 `ns_signal_t.mutex` / `ns_loop_t.wakeup` / `ns_loop_t.async_thread` / `ns_timer_mgr.mutex` / `ns_dbg_mutex` 五个**成员**在裸机下不参与编译，其调用点在既有汇点处一并屏蔽。

- **Pros:** 字面满足 spec:52 与 spec AC3；无虚构对象**也无虚构动词**（P2 最强形态）；`nm` 干净；`src/` 的屏蔽工作量与其它方案相同（汇点一样要 `#ifdef`）。
- **Cons:** `NANOSIG_BAREMETAL` 出现在一个公开头的成员守卫处（已在 P1 显式规定）；`src/` 约 20 处条件编译。

#### 其余方案（均已否决）
- **E（哑类型保留成员）** —— 唯一独有卖点"布局跨后端一致"实测为假（`sizeof(ns_signal_t)`：host 112 B vs 哑类型约 56 B）；违反 spec:52/AC3 字面要求。
- **B / D（运行期空桩，`ns_platform_mutex_lock` 返 `NS_OK`）** —— 违反 P2 与 spec:51；空 mutex 静默掩盖并发误用。
- **B′（`static inline` 空锁放在裸机平台头）** —— 技术合法（C11 §6.2.2 p4/p5，`nm -g` 不可见，零警告），但语义就是 B 的空桩换了链接属性；"绕过 `nm`"不能算"机器可验证"。
- **C（signal+timer 抽成 header-only 分叉）** —— 违反 P3 与 `docs/ARCHITECTURE.md` §1；测试负担翻倍。
- **S（同步直调 emit + `ns_timer_tick(now)`）** —— 架构上更简（约 30 行、零 `#ifdef`），但 **spec Round 4 已由用户明确否决**（"异步派发语义必须保留"，`spec:89`，并固化为 AC8）。本计划不得重新审理已决需求；若日后要改，走 **spec 修订请求**，不是本计划。

## 3. Implementation Steps

> **Step 0 必须最先做完**：它是 C14/C21 这类"头文件根本编不过"的最廉价捕获点。

### Step 0 — 建立裸机语法检查靶子
在 `CMakeLists.txt` 增加裸机 `-fsyntax-only` 目标（带 `platform/baremetal` include 路径），先让它对空后端失败，再逐步补齐。**完成判据：该目标干净通过。**

### Step 3 — loop：成员屏蔽 + 静态单例 + `ns_loop_poll`
**Files:** `src/nanosig.c`、`include/nanosig/nanosig_loop.h`

- `struct ns_loop` 的 `ns_platform_wakeup_t wakeup;`（`:24`）与 `ns_platform_thread_t async_thread;`（`:29`）→ `#ifndef NANOSIG_BAREMETAL`（后者被静态 `g_bm_loop` 实例化，不屏蔽就与 Step 1 "不会有运行期实例"的说法矛盾）。
- `struct ns_loop` 增 `int created;`（**全后端**，`ns_loop_t` 是 opaque，无 ABI 影响）。**host 路径也必须维护它**：`ns_loop_create` 成功时置 1，`ns_loop_destroy` 置 0，否则两种后端的取值不一致。
- `ns_loop_create`（`:144`）裸机分支：
  ```c
  static struct ns_loop  g_bm_loop;
  static _Alignas(NS_MPSC_RECORD_RING_ALIGNMENT)
         uint8_t         g_bm_ring_storage[NANOSIG_BAREMETAL_LOOP_QUEUE_BYTES];
  ```
  **顺序：`created` 判定必须在 `ns_loop_config_validate` 之前**（否则二次 create 带不同 capacity 会返回 `NS_E_INVAL` 而非 `NS_E_EXISTS`）。
  首次进入后仍须：`loop->config = local_config`、`ns_atomic_init(quit_requested/running)`、`async_started = 0`、`async_rc = NS_OK`、`ns_mpsc_record_ring_init(&loop->queue, g_bm_ring_storage, (ns_capacity_t)NANOSIG_BAREMETAL_LOOP_QUEUE_BYTES)`。**不调用 `ns_platform_alloc` / `ns_platform_wakeup_init`。**
  `out_loop` 的处理与宿主一致（`:152` 先置 NULL，`:181` 成功时写入）。
- `ns_loop_config_validate`（`:75-94`）：
  - `stack_size` 分支 `:85-91`（`:88` 调 `ns_platform_thread_stack_range`）→ `#ifdef NANOSIG_BAREMETAL` 分支返回 `stack_size != 0 ? NS_E_INVAL : NS_OK`（不静默忽略公开字段）。
  - **不要**在裸机分支里给 `config == NULL` 开后门——`ns_loop_create:156` 已统一替换为 `NS_LOOP_CONFIG_DEFAULT()`，validate 永远看不到 `NULL`；保留 `:81` 的既有 host 不变量。
  - 容量上限校验放在**裸机 create 内、created 判定之后、首次初始化之前**：`queue_byte_capacity > NANOSIG_BAREMETAL_LOOP_QUEUE_BYTES` → `NS_E_INVAL`（用 `>` 不用 `!=`——`NS_LOOP_CONFIG_DEFAULT()` 是 `NS_CAPACITY_1024`，`nanosig_loop.h:69`）。
- `ns_loop_destroy`（`:189`）裸机分支：**与 host 同语义**——`created == 0 → NS_E_INVAL`；否则 `created = 0` 并丢弃 ring 内容（不做额外回收），返回 `NS_OK`。**不引入 `NS_E_BUSY`**（见 §7 ADR 否决记录）。可诊断性交给 Follow-up 的 `ns_loop_stats()`。
- 整块 `#ifndef NANOSIG_BAREMETAL`：`:229` 至 `:334`（`ns_loop_run_impl` / `ns_loop_run` / `ns_loop_quit`（含 `:284` 的 `wakeup_signal`）/ `ns_loop_start` / `ns_loop_stop` / `ns_loop_async_entry`（`:291-296`））。**`ns_loop_dispatch_pending`（`:206-227`）不得被屏蔽。**
- `ns_signal_lock` / `ns_signal_unlock`（`:56-66`）→ 裸机版：
  ```c

  {

      (void)signal;          /* -Wextra -Wunused-parameter */
  ```

- emit 路径 `ns_platform_wakeup_signal`（`:474`）→ `#ifndef`。
- `ns_init` / `ns_shutdown`：`#ifndef` 包住 `ns_broker_global_init`（`:113`）/ `ns_broker_global_shutdown`（`:133`）；裸机分支改为 `ns_timer_mgr_global_init(NULL, NULL)` / `ns_timer_mgr_global_shutdown()`，顺序镜像 broker 侧（`ns_broker.c:548` → `:559/:602`）。**`ns_shutdown` 裸机分支还须重置 `g_bm_loop.created = 0`**，避免 loop 停在半创建态跨 init/shutdown 周期存活。
- 新增（`#ifdef NANOSIG_BAREMETAL`）：
  ```c
  int ns_loop_poll(ns_loop_t *loop, uint32_t max_wait_us)
  {
      int      rc = NS_OK;
      int      i;
      uint64_t t = 0u;
      (void)max_wait_us;   /* 契约上界：本函数从不睡眠，睡眠是调用方结合 ns_loop_next_timeout 的事 */

      if(loop == NULL) return NS_E_INVAL;
      if(!ns_is_initialized()) return NS_E_SHUTDOWN;
      if(!loop->created) return NS_E_INVAL;

      for(i = 0; i < NANOSIG_BAREMETAL_POLL_MAX_ROUNDS; i++){
          int n = ns_timer_mgr_fire_expired();      /* 先把到期 timer 的 emit 入队 */
          if((n != NS_OK) && (rc == NS_OK)) rc = n; /* 错误不得被吞 */
          ns_loop_dispatch_pending(loop);           /* 再 drain + 派发（含 timer slot） */
          if((ns_timer_mgr_next_timeout(&t) != NS_OK) || (t > 0u)) break;
      }
      return rc;
  }

  int ns_loop_next_timeout(ns_loop_t *loop, ns_platform_time_us_t *out_us)
  {
      int rc;
      if((loop == NULL) || (out_us == NULL)) return NS_E_INVAL;
      if(!loop->created) return NS_E_INVAL;
      rc = ns_timer_mgr_next_timeout(out_us);
      if(rc == NS_E_NO_TIMER){                     /* :242-245 不写 *out，必须补齐 */
          *out_us = NS_PLATFORM_WAIT_INFINITE_US;
          return NS_OK;
      }
      return rc;
  }
  ```
  **轮次顺序是硬要求**：`fire_expired` 经 `ns_signal_emit_raw`（`src/ns_timer.c:299`）往 ring 入队，回调只有在随后的 dispatch 里才跑。
  `NANOSIG_BAREMETAL_POLL_MAX_ROUNDS`（默认 4）在耗尽时静默返回 `NS_OK`（若仍有到期项）——由文档说明上界语义。

### Step 4 — timer：成员屏蔽 + 初始化
**File:** `src/ns_timer.c`

- `struct ns_timer_mgr` 的 `ns_platform_mutex_t mutex;`（`:21`）→ `#ifndef`。
- `ns_timer_mgr_lock` / `unlock`（`:70-86`）按完整替换给出裸机体（保留 `!initialized → NS_E_SHUTDOWN`，`unlock` 里同样 `(void)` 掉未用参数）。
- `ns_timer_mgr_global_init`（`:178`）裸机体：`(void)notify; (void)ctx;` 后直接 `g_timer_mgr.initialized = 1;`（`:196` 必须保留）并 `return NS_OK;`。
- `ns_timer_mgr_global_shutdown`（`:200`）**必须用 `#ifdef/#else/#endif` 整块替换，不能跨 `if` 花括号拆**（`:211` 是 `if` 的条件表达式）：
  ```c
  #ifdef NANOSIG_BAREMETAL
      while((node = ns_rbtree_first(&g_timer_mgr.tree)) != NULL){
          ns_rbtree_del(node, &g_timer_mgr.tree);
      }
      /* g_timer_mgr.mutex 不存在，无 deinit */
  #else
      if(ns_platform_mutex_lock(&g_timer_mgr.mutex) == NS_OK){
          while((node = ns_rbtree_first(&g_timer_mgr.tree)) != NULL){
              ns_rbtree_del(node, &g_timer_mgr.tree);
          }
          (void)ns_platform_mutex_unlock(&g_timer_mgr.mutex);
      }
      (void)ns_platform_mutex_deinit(&g_timer_mgr.mutex);
  #endif
  ```
  跳过清树会让所有 timer 节点永久标记为 running，`ns_timer_start` 之后永远返回 `NS_E_EXISTS`。
- **不新增任何到期派发函数**——复用 `ns_timer_mgr_fire_expired`（`:273`）。

### Step 5 — debug / formatio
**Files:** `src/ns_debug.c`、`src/ns_formatio.c`

## 7. ADR

**Decision:** 采用 **Option A′**。`platform/baremetal/` 提供 4 个哑平台类型（仅供 `nanosig_port.h` 的函数声明）+ `ns_waitable_handle_t` + `NS_PLATFORM_ABI_PROBE` + 3 个 `ns_platform_*` 符号；`ns_signal_t.mutex`、`ns_loop_t.wakeup`、`ns_loop_t.async_thread`、`ns_timer_mgr.mutex`、`ns_dbg_mutex` 五个成员及全部调用点用 `NANOSIG_BAREMETAL` 屏蔽，涉及函数按完整替换给出裸机体；loop 改静态单例；新增 `ns_loop_poll` / `ns_loop_next_timeout`，内部复用既有的 `ns_timer_mgr_fire_expired`。

**Drivers:** D1 机器可验证（`nm` ∩ 集合 + 链接失败 + `-Werror`）；D2 与既有 5 后端同构；D3 host harness 可测。

**Alternatives considered:**
- **E（哑类型保留成员）** —— 独有卖点"布局一致"实测为假；违反 spec:52/AC3 字面。
- **B / D（运行期空桩）** —— 违反 P2 与 spec:51。
- **B′（`static inline` 空锁）** —— 合法但语义即 B，且"绕过 `nm`"自我否定。
- **C（header-only 分叉）** —— 违反 P3 与 `docs/ARCHITECTURE.md` §1。
- **S（同步直调 emit + `ns_timer_tick`）** —— 架构最简，但 spec Round 4 用户已明确否决（`spec:89`），本计划无权重审；归入 follow-up 的 spec 修订请求。
- **`ns_loop_destroy` 遇非空 ring 返 `NS_E_BUSY`** —— 已否决：它是 host 没有的错误码（违反 P3），且 `ns_shutdown()` 后 `poll` 返回 `NS_E_SHUTDOWN` 会让单例永久既不可 destroy 也不可 create。改为与 host 同语义丢弃。

**Why chosen:** A′ 是唯一**字面满足** spec:52 与 spec AC3 的方案，同时满足三条硬约束与 P2 的最强形态（既无虚构对象也无虚构动词）；且 `src/` 工作量与其它方案相同。

**Consequences:**
- 正向：`nm` 真实反映能力；裸机下结构体不含死状态；能力边界全部机器可断言；`destroy` 语义跨后端一致。
- 负向：`NANOSIG_BAREMETAL` 出现在一个公开头的成员守卫处（已写入 `docs/ARCHITECTURE.md`）；`src/` 约 20 处条件编译。
- 需接受：单 loop 实例 ⇒ 子系统间队头阻塞、容量不可按需调整；`ns_formatio` 超长格式化在裸机上输出为空（spec AC3 指定）；真实交叉工具链链接未验证（R9，显式非目标）。

**Follow-ups:**
- ISR 上下文 emit（`*_from_isr`）当前显式 deferred，是保留 ring 的长期理由。
- 若 ring 容量成为瓶颈：分级配置或 `ns_loop_stats()` 暴露丢弃计数（也是 `destroy` 可诊断性的正确归宿）。
- 若确需交叉工具链保证：补 `arm-none-eabi` 的 `-fsyntax-only` + 链接列。
- 若日后要重新评估"同步直调 emit"简化路线：作为 **spec 修订请求**提出，不在本计划范围内。
