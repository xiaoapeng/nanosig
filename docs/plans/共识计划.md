## 目标

nanosig 是一个全新的 C11 signal/slot 库。它借鉴 `tmp/eventhub_os` 的代码风格和部分基础设施思想，但不追求 `eh_*` 源码兼容。v1 的目标交付物是：

- Linux + macOS + Windows 可构建、可测试的 C11 库；
- loop 由调用方显式传参管理，不再依赖线程绑定或平台 TLS；
- signal emit 可跨线程进入目标 loop；
- 可变长 MPSC record ring；
- P5 之后由 `ns_event_broker_t` 独立管理外部事件源，平台 waitset 等待 readiness，broker 将 timer、文件描述符、socket 或平台 handle 事件转换为 signal emit，loop 只负责执行连接到它的 slot；
- ASAN/TSAN/UBSAN/AppVerifier 方向的验证入口；
- 三个验收 demo：同线程 signal、跨线程 signal、timer 跨线程触发。

## 已锁定公开 API 决策

### 线程与 loop

- 公开类型名保持 `ns_loop_t`。
- loop 不绑定线程，调用方通过显式传参管理 loop 生命周期。
- `ns_loop_create` 创建 loop，不绑定当前线程；调用方负责决定哪个线程 run 哪个 loop。
- `ns_loop_run(ns_loop_t *loop)` 接受显式 loop 参数。
- `ns_loop_quit(ns_loop_t *loop)` 接受显式 loop 参数，可跨线程调用。
- 已移除 `ns_loop_current`、`ns_loop_is_owner`、内部 loop manager 注册表和平台 TLS。

### signal / slot

- 公开操作统一使用 `ns_signal_*` 前缀。
- 函数包装宏使用小写，例如：
  - `ns_signal_connect_typed`
  - `ns_signal_emit`
  - `ns_signal_init`
  - `ns_signal_deinit`
- 声明、payload 元数据、类型检查宏保持大写，例如：
  - `NS_SIGNAL_DECLARE`
  - `NS_DEFINE_SLOT`
  - `NS_SIGNAL_PAYLOAD_SIZE`
  - `NS_SIGNAL_PAYLOAD_PTR_SIZE`
  - `NS_SLOT_TYPECHECK`
- `ns_signal_connect_typed` 显式指定目标 loop（loop 不绑定线程，无隐式路径）。
- 底层连接函数只有一个：
  - `ns_signal_connect(signal, slot_fn, target_loop, user_data, connection)`
- `connection` 是调用方拥有的 `ns_connection_t *`，库不分配连接内存。
- `target_loop` 必须非空；loop 不绑定线程，不存在隐式当前线程 loop。
- typed connect 在 C11 下使用 `_Generic` 做编译期 slot 签名检查。
- raw connect / raw emit 是给实现层、绑定层、适配层使用的逃生通道。

### payload 与 no-payload

- signal 的 payload 大小由公开宏在编译期烘焙。
- 普通 payload 使用显式结构体类型。
- no-payload 使用 `ns_no_payload_t` 作为类型标记。
- `ns_no_payload_t` 不是可拷贝 payload 对象。
- `NS_NO_PAYLOAD` 是唯一的 no-payload emit 入参。
- `NS_SIGNAL_PAYLOAD_SIZE(ns_no_payload_t)` 必须为 0。
- `NS_SIGNAL_PAYLOAD_PTR_SIZE(NS_NO_PAYLOAD)` 必须为 0。
- no-payload emit / timer 路径必须拷贝 0 字节。
- 不使用 `reserved[0]` 或其他零长数组技巧。

### signal 生命周期

- `ns_signal_t` 可以静态定义，也可以作为用户结构体成员，但使用前必须显式初始化。
- 独立静态对象、自动变量、堆对象和结构体成员都使用 `ns_signal_init(signal, payload_type)` 或底层 `ns_signal_init_raw` 初始化。
- 成功初始化的 signal 拥有内部 mutex；销毁承载对象前必须先断开连接，再调用 `ns_signal_deinit(signal)` / `ns_signal_deinit_raw(signal)`。
- `ns_signal_init_raw` / `ns_signal_init` 与对应 deinit 不支持在同一个 signal 对象上并发调用；初始化生命周期由调用方串行化。
- `ns_signal_disconnect` 将连接从 signal 的 slot_list 移除但不释放内存。
- `ns_connection_t` 由调用方拥有存储（栈变量、堆分配或嵌入用户结构体均可）。
- `ns_signal_disconnect_all` 可以作为 teardown / 逃生通道存在，但健康程序通常应保存连接对象并逐个 `ns_signal_disconnect`。
- disconnect 不取消已经入队的 slot 调用；`user_data` 生命周期必须长于任何 in-flight emit。

### timer

- `ns_timer_t` 是调用方自持存储，不是不透明分配句柄。
- `ns_timer_t` 的第一个字段必须是：

```c
ns_signal_t signal;
```

- timer 到期时触发这个内嵌 no-payload signal。
- timer 只支持无参数触发。
- 创建接口为：

```c
int ns_timer_create(ns_timer_t *timer, ns_time_us_t interval_us, uint32_t attr);
```

- `ns_time_us_t` 是 `uint64_t` 微秒。
- `attr` 是位图：
  - bit0：`NS_TIMER_ATTR_REPEAT`，是否重复；
  - bit1：`NS_TIMER_ATTR_RELOAD_FROM_NOW`，重复重装载时以当前时间为基准，否则优先使用上一次 deadline 步进。
  - 值 0：`NS_TIMER_ATTR_ONESHOT`，单次触发后停止。
- bit1 未设置时，下一次 deadline 优先为 `previous_deadline + interval_us`；如果该时间已经落后于当前时间，则退化为 `now + interval_us`。
- `ns_timer_create` 只初始化 timer 对象（含内嵌 signal 的 mutex），不自动启动。
- `ns_timer_start` 将 timer 注册到 timer_mgr，到期后触发内嵌 signal。
- `ns_timer_cancel` 对任何成功 `ns_timer_create` 的 timer 都合法；未运行时返回成功且无副作用。
- `ns_timer_restart` 若 timer 未运行则等价于 start；若正在运行则先移除旧 deadline 再以当前时间重新装载。
- `ns_timer_destroy` 停止仍在运行的 timer 并释放内嵌 signal 的内部资源。

### watcher

- `ns_watcher_t` 是调用方自持存储，不是不透明分配句柄。
- `ns_watcher_t` 的第一个字段必须是：

```c
ns_signal_t signal;
```

- watcher 事件触发时 emit 这个内嵌 signal，payload 为 `ns_watcher_event_t`。
- `ns_watcher_event_t` 包含 `uint32_t triggered_events`（`NS_WAITABLE_EVENT_IN/OUT/ERR` 组合）。
- `NS_WAITABLE_EVENT_IN`、`NS_WAITABLE_EVENT_OUT`、`NS_WAITABLE_EVENT_ERR` 从 `platform/port.h` 提升到公开头文件。
- watcher 的 signal payload 有内容（events），不是 no-payload。
- 初始化接口有两个：

```c
int ns_watcher_init_fd(ns_watcher_t *watcher, int fd, uint32_t events, int edge_triggered);
int ns_watcher_init_handle(ns_watcher_t *watcher, void *handle, uint32_t events, int edge_triggered);
```

- `events` 是 `NS_WAITABLE_EVENT_IN/OUT/ERR` 的位组合。
- `edge_triggered`：1 = 边沿触发（Linux `EPOLLET` / macOS `EV_CLEAR`），0 = 电平触发。
- `ns_watcher_init_*` 内部自动调 `ns_signal_init_raw` 初始化内嵌 signal。
- `ns_watcher_deinit` 释放 signal 内部资源并重置 waitable。
- `ns_watcher_deinit` 前必须先 `ns_broker_remove`。
- `ns_watcher_deinit` 只对成功初始化的 watcher 返回成功；`ns_watcher_init_*` 失败时会把 watcher 重置为空未初始化状态，随后 `deinit` 返回 `NS_E_INVAL`。
- `ns_watcher_t` 内含 `ns_platform_waitable_t` 和 `ns_list_node_t broker_node`；`waitable` 由 init 函数填充，`broker_node` 由 broker 内部使用。
- `ns_platform_waitable_t` 直接暴露并内嵌在 `ns_watcher_t` 中（方案 A），不增加 opaque 私有包装；用户通过 `ns_watcher_init_*` 封装平台差异，通常不需要直接访问平台句柄成员。
- `ns_watcher_init_fd` / `ns_watcher_init_handle` 都保留为正常公开初始化入口，不引入 `NS_E_UNSUPPORTED` 或按平台隐藏符号；参数有效时初始化 signal、waitable 和 broker_node。调用方负责在当前平台传入对应 waitset 后端可等待的 fd / HANDLE。

### event broker

- `ns_event_broker_t` 是全局单例，随 `ns_init()` 初始化，随 `ns_shutdown()` 销毁。
- `ns_broker_add` / `ns_broker_remove` 自动访问全局 broker，调用方无需 `ns_broker()`。`ns_broker()` 已移入内部头。
- broker 拥有：1 个线程 + 1 个 waitset + 1 个 wakeup（注册到自己的 waitset）+ timer_mgr。
- broker 与 loop 完全解耦；broker 不直接操作 loop 的 wakeup 或 MPSC ring，所有投递通过 signal emit 完成。
- broker 与 timer_mgr 完全解耦；timer_mgr 通过 `ns_timer_notify_fn` 回调唤醒 broker。
- broker 公开接口：

```c
ns_event_broker_t *ns_broker(void);
int ns_broker_add(ns_watcher_t *watcher);
int ns_broker_remove(ns_watcher_t *watcher);
```

- `add` 注册 watcher 到 broker 的 waitset；同一 watcher 重复 add 返回 `NS_E_EXISTS`。
- `remove` 从 waitset 注销 watcher，并由平台层清除 `waitable.registered_waitset`；已入队的 slot 调用不撤回（与 `ns_signal_disconnect` 语义一致）。
- `add` 内部设置 `watcher->waitable.user_data = watcher`，broker 主循环通过 `user_data` 从 completion 回找 watcher。
- broker 线程错误（`waitset_wait` 或 `fire_expired`）continue 不退出。
- broker 初始化时先完成对象初始化和 broker 线程创建，再发布 `g_broker`；timer notify 使用非空 ctx 指向 broker，不依赖 `g_broker` 提前可见。若线程创建或更早步骤失败，失败路径必须清理已创建资源且不得发布 `g_broker`。
- `ns_shutdown` 时 broker 销毁前要求所有 timer 已 destroy、所有 loop 已 destroy；watcher 应由调用方先 remove。若仍有 watcher 残留，broker 销毁路径必须把它们从 waitset 注销并重新初始化 `broker_node`，防止 waitset 保留悬挂 waitable。
- 详细设计见 `docs/BROKER_DESIGN.md`。

### v1 safety 策略

- v1 公开头文件不暴露 `__safety` 注解。
- `include/nanosig/nanosig_safety.h` 仅保留未来 safety 扩展点。
- 当前 v1 实现不以“中断中发射 signal”为目标，不提供 `*_from_isr` API，也不承诺 public emit 可在 ISR 中调用。
- emit 路径保持零运行时分配，用于降低延迟和保留未来扩展空间；这不是 v1 的 ISR 支持承诺。

## 示例与反初始化规则

所有获取多个 nanosig 资源的示例必须使用内核风格 `goto` 清理标签。原则是：

- 每个成功初始化的资源都有对应清理路径；
- create 失败不清理未创建对象；
- timer create 成功后可以直接在清理路径调用 `ns_timer_cancel`，无需 `timer_started` 标志；
- timer create 成功后 `ns_timer_destroy` 必须可达；
- connection 成功后才进入 `ns_signal_disconnect` 清理路径。

#### broker 架构

broker 是全局单例，管理事件等待和分发：

- v1：1 个线程 + 1 个 waitset + 1 个 timer_manager。
- v2 扩展：N 个线程 + N 个 waitset，其中 1 个负责 timeout（timer waitset），其余等待无限（IO waitset）。add 时按策略分配到某个 waitset。

```
ns_init() 时：
  broker_init()  → 创建线程 + waitset + timer_manager

ns_shutdown() 时：
  broker_destroy() → 停止线程 + 销毁 waitset + 销毁 timer_manager
```

```
┌─────────────────────────────────────────────────┐
│              ns_event_broker_t (全局单例)         │
│                                                  │
│  ┌──────────────┐  ┌──────────────┐              │
│  │  thread[0]   │  │  waitset[0]  │  ← v1 唯一  │
│  │  (未来可扩展) │  │  (timeout +  │              │
│  │              │  │   外部事件)   │              │
│  └──────────────┘  └──────────────┘              │
│                                                  │
│  ┌──────────────────────────────────┐            │
│  │  ns_timer_mgr_t (rbtree)         │            │
│  │  next_deadline() → μs            │            │
│  │  fire_expired(now) → emit signal │            │
│  │  add/remove → wakeup signal      │            │
│  └──────────────────────────────────┘            │
│                                                  │
│  broker_run 主循环：                              │
│    1. deadline = timer_mgr_next()                │
│    2. waitset_wait(deadline)                     │
│    3. process completions（外部事件）             │
│    4. drain MPSC queue（signal/slot dispatch）    │
│    5. timer_mgr_fire_expired()                   │
│    6. loop                                       │
│                                                  │
│  跨线程 timer add/remove → wakeup signal          │
│  → broker 重新计算 timeout                        │
└─────────────────────────────────────────────────┘

┌──────────────────────────────────────┐
│           ns_loop_t                   │
│  MPSC queue + wakeup                 │
│                                      │
│  ns_loop_run:                        │
│    wakeup_wait() → 等 broker 唤醒    │
│    dispatch_pending()                │
│    loop                              │
└──────────────────────────────────────┘
```

三层职责分离：loop 只管 MPSC dispatch，broker 负责所有等待和事件源，timer_manager 负责 deadline 管理。loop 不知道 timer 的存在，broker 不碰 rbtree，timer_manager 不依赖 broker 或 loop。

#### waitset 接口设计

三层概念模型：

- **waitset** — 一次等待多个事件源的容器（Linux epoll / macOS kqueue / Windows WaitForMultipleObjects / RTOS event group）。
- **waitable** — 完整的"等待描述符"：平台原语 + user_data + registered_waitset + events + edge_triggered。
- **completion** — 一次 wait 返回的事件结果。

waitable 是 struct，包含所有注册信息。`add` 接受非 const 指针（零拷贝），caller 保证
waitable 在 remove 前一直有效。注册成功后平台层写入 `registered_waitset`，同一
waitable 同一时间只能注册到一个 waitset。Linux 后端通过 epoll `data.ptr` 直接引用
caller 的 waitable，macOS 后端通过 kevent `udata` 直接引用 caller 的 waitable，
Windows 后端内部存指针做 index 映射。

```c
typedef struct ns_platform_waitable {
    union {
        int     fd;         /* Linux/macOS: 文件描述符 */
        void   *handle;     /* Windows: HANDLE */
        int     event_bit;  /* RTOS: event bit index（v2） */
    };
    void    *user_data;
    void    *registered_waitset;
    uint32_t events;        /* NS_WAITABLE_EVENT_* */
    int      edge_triggered;
} ns_platform_waitable_t;

static inline void ns_waitable_init(ns_platform_waitable_t *w);
```

completion 指向 caller 的 waitable（零拷贝）：

```c
typedef struct ns_platform_waitset_completion {
    const ns_platform_waitable_t *waitable;         /* 指向注册时的 waitable */
    uint32_t                      triggered_events; /* 实际触发的事件位 */
} ns_platform_waitset_completion_t;
```

事件语义使用最小公共事件位：

```c
#define NS_WAITABLE_EVENT_IN   (1u << 0)  /* 可读 / signaled */
#define NS_WAITABLE_EVENT_OUT  (1u << 1)  /* 可写 */
#define NS_WAITABLE_EVENT_ERR  (1u << 2)  /* 错误 */
```

- Linux：add 时把 `NS_WAITABLE_EVENT_IN` 映射到 `EPOLLIN`，completion 的 events 翻译回来。
- Windows：`WaitForMultipleObjects` 返回 signaled → 设置 `NS_WAITABLE_EVENT_IN`。
- RTOS（v2）：event group bit fired → 设置 `NS_WAITABLE_EVENT_IN`。

waitset 完整接口：

```c
typedef struct ns_platform_waitset ns_platform_waitset_t;

int ns_platform_waitset_create(ns_platform_waitset_t **out_waitset);
int ns_platform_waitset_destroy(ns_platform_waitset_t *waitset);

int ns_platform_waitset_add(
    ns_platform_waitset_t *waitset,
    ns_platform_waitable_t *waitable);

int ns_platform_waitset_remove(
    ns_platform_waitset_t *waitset,
    ns_platform_waitable_t *waitable);

int ns_platform_waitset_wait(
    ns_platform_waitset_t *waitset,
    ns_platform_time_us_t timeout_us,
    ns_platform_waitset_completion_t *completions,
    size_t max_completions,
    size_t *out_count);
```

- `add`/`remove` 接受非 const 指针，零拷贝。caller 保证 waitable 在 remove 前有效。
- 注册成功后平台层维护 `registered_waitset`，同一 waitable 已注册时 `add` 返回 `NS_E_EXISTS`。
- `destroy` 要求 waitset 为空；仍有注册项时返回 `NS_E_EXISTS`，避免 waitable 注册状态悬挂。
- `completions` 由调用方提供（栈上数组），平台层往里写。
- `max_completions` 是数组容量，`out_count` 返回实际触发数。
- timeout 为 0 → 非阻塞检查；`NS_PLATFORM_WAIT_INFINITE_US` → 无限等待。

#### timeout 语义

`ns_platform_waitset_wait` 的 timeout 单位为微秒。后端实现时映射到平台原生等待能力：

- Linux：预创建 `timerfd` 并加入 epoll，有限 timeout 通过 `timerfd_settime` arm。
- macOS：`kevent` 直接接收 `timespec` timeout，不需要额外 timer waitable。
- Windows：`WaitableTimer` 加入 `WaitForMultipleObjects` 数组。
- RTOS（v2）：`xEventGroupWaitBits` 接受 tick，按 tick 周期换算。

实现必须避免早于 `timeout_us` 返回导致忙等；实际返回可能因平台计时器和调度延迟略晚。晚 fire 是安全的（broker 检查 deadline < now 后立刻 fire）。

v1 验收场景为 100ms 级重复 timer；微秒入参保留给 broker deadline 计算，实际精度由后端计时器和系统调度决定。

#### RTOS 前向兼容

RTOS 等待模型与 Linux/Windows 不同，但接口可映射：

| 概念 | Linux | macOS | Windows | RTOS (v2) |
|------|-------|-------|---------|-----------|
| waitset | epoll fd | kqueue fd | handle array | event group |
| waitable | fd | fd | HANDLE | event bit index |
| wait | epoll_wait + timerfd | kevent | WaitForMultipleObjects + WaitableTimer | xEventGroupWaitBits |

`ns_platform_waitable_t` 的 `event_bit` 字段为 RTOS 预留。RTOS 后端的 `ns_platform_wakeup_get_waitable` 返回 `event_bit=0`（wakeup 占 bit 0）。

RTOS event group 通常有 bit 数量上限（FreeRTOS 24 bit），通过 `ns_platform_waitset_create` 的输出参数或后端内部文档表达容量限制，不在 `port.h` 头文件中暴露编译期平台宏。

RTOS ISR 安全是 v2 课题，v1 不承诺。`ns_platform_waitset_add` / `remove` 不需要 ISR-safe（只在初始化时调用）。

#### 与 timer 的关系

timer 不注册为 waitable。timer 触发靠 `ns_platform_waitset_wait` 的 timeout 参数：broker 从 timer_manager 取最近 deadline，计算 timeout，传给 wait。wait 返回后 broker 检查过期 timer 并 fire。

跨线程创建/取消 timer 时，通过 timer_mgr notify 回调唤醒 broker 自身的 wakeup，使其重新计算 timeout。详见 P6 timer 架构。

#### timer_manager 架构

`ns_timer_mgr_t` 是独立模块，自身维护全局单例，通过回调通知 broker：

```c
typedef void (*ns_timer_notify_fn)(void *ctx);

struct ns_timer_mgr {
    ns_platform_mutex_t   *mutex;
    ns_rbtree_t            tree;         /* 按 remaining time 排序 */
    ns_platform_time_us_t  now;          /* 操作前刷新，操作内不变 */
    ns_timer_notify_fn     notify;       /* broker 注册的回调 */
    void                  *notify_ctx;
};

/* 给 broker 调用的生命周期 */
int  ns_timer_mgr_global_init(ns_timer_notify_fn notify, void *ctx);
void ns_timer_mgr_global_shutdown(void);

/* 给 broker 调用的运行时 */
int  ns_timer_mgr_next_timeout(ns_platform_time_us_t *out_timeout_us);
int  ns_timer_mgr_fire_expired(void);
```

- `global_init`：创建 mutex、初始化 rbtree、注册回调。broker 在 `ns_init()` 时调用。
- `global_shutdown`：销毁 mutex、清空 rbtree。broker 在 `ns_shutdown()` 时调用。
- `next_timeout`：返回最近 timer 的 remaining time（微秒）。无 timer 返回 `NS_E_NO_TIMER`。
- `fire_expired`：内部取 `now`，fire 所有 `remaining ≤ 0` 的 timer，repeat timer 重新插入。
- 跨线程 add/remove 时内部调 `notify(notify_ctx)` 通知 broker。

#### rbtree 排序

comparator 用**相对时间**（remaining time），不用绝对 deadline。unsigned 减法天然处理
时钟绕回（wraparound），`(uint64_t)(expire - now)` 在绕回时仍算出正确距离。

`mgr->now` 在每次 mutex 操作前刷新，comparator 用它算 remaining time，操作内时间一致。

#### broker_run 主循环

broker_run 主循环使用 timer_manager 的方式：

```
1. rc = timer_mgr_next_timeout(&timeout)
   if rc == NS_E_NO_TIMER → timeout = INFINITE
2. waitset_wait(waitset, timeout, ...)
3. process completions（外部事件）
4. drain MPSC queue（signal/slot dispatch）
5. timer_mgr_fire_expired()    ← 内部取时间，内部 fire
6. loop
```

#### 架构总览

```
┌─────────────────────────────────────────────────────┐
│                ns_event_broker_t (全局单例)           │
│                                                      │
│  ┌──────────────┐  ┌──────────────┐                  │
│  │  thread       │  │  waitset      │                  │
│  └──────────────┘  └──────────────┘                  │
│                                                      │
│  ┌──────────────────────────────────────┐            │
│  │  watcher_list (双向链表)              │            │
│  │  每个 watcher 内嵌 waitable + signal │            │
│  └──────────────────────────────────────┘            │
│                                                      │
│  ┌──────────────────────────────────────┐            │
│  │  ns_timer_mgr_t (rbtree)  [内置]     │            │
│  │  next_timeout() → μs                 │            │
│  │  fire_expired() → emit timer signal  │            │
│  │  start/cancel/restart → notify       │            │
│  └──────────────────────────────────────┘            │
│                                                      │
│  broker_run 主循环：                                  │
│    1. timeout = timer_mgr_next_timeout()             │
│    2. waitset_wait(timeout)                          │
│    3. 遍历 completions → emit watcher signal         │
│    4. timer_mgr_fire_expired()                       │
│    5. loop                                           │
│                                                      │
│  notify 回调链：                                      │
│    timer start/cancel/restart                        │
│    → timer_mgr notify(ctx)                           │
│    → ns_broker_notify()                              │
│    → wakeup_signal(broker->wakeup)                   │
│    → waitset_wait 返回 → 重新计算 timeout             │
└─────────────────────────────────────────────────────┘

┌──────────────────────────────────────┐
│           ns_loop_t                   │
│  MPSC queue + wakeup                 │
│                                      │
│  ns_loop_run:                        │
│    wakeup_wait() → 等 signal 唤醒    │
│    dispatch_pending()                │
│    loop                              │
└──────────────────────────────────────┘
```

三层各司其职，单向依赖，没有环。loop 不知道 timer 或 watcher 的存在，broker 不碰 rbtree，timer_manager 不依赖 broker 或 loop。broker 通过 signal emit 投递所有事件，不直接操作 loop 的 wakeup 或 MPSC ring。

### 编码治理

本仓库源码、头文件、测试、CMake 和 Markdown 文档统一使用 UTF-8。新文件和编辑后的文本文件优先保持 UTF-8 without BOM。

这次 P2 数据结构迁移暴露的教训：

- 严格 UTF-8 解码通过，不代表中文内容正常；中文注释可能已经是 mojibake；
- PowerShell `Set-Content` / `Out-File` 等批量写入命令如果没有显式指定编码，可能改变编码或行尾；
- `git ls-files` 默认可能转义中文文件名，编码检查脚本要使用 `git -c core.quotePath=false ...`，并过滤工作树中已删除的路径；
- 修复编码问题时只修文本，不顺手改实现逻辑。

后续任何批量替换、跨 shell 文件重写、从参考代码迁移中文注释之后，至少执行：

```powershell
# 严格 UTF-8 解码检查：所有 Git 可见且仍存在的文件必须可被 strict UTF-8 解码。
# 乱码特征扫描：至少覆盖 include/src/test/docs/platform/cmake/demos/bench 和顶层工程文件。
```

推荐使用 `apply_patch` 做人工编辑；确需脚本写文件时，必须显式使用 UTF-8 writer，并在写完后立即重跑上述两类检查。

### P5b event broker 追加协议

broker / waitset 不阻塞 P1b-P5。只有在 signal / slot 已完成后，且 timer broker、fd/socket readiness 或平台 handle readiness 进入实现时，才追加 `ns_event_broker_t` / waitset 契约。追加只允许处理等待模型、event source 注册、broker 到 signal 的投递边界和 timer 事件源边界，不允许顺手改公开 signal / timer API。

waitset 契约追加到 `platform/port.h`，不拆分 `broker_port.h`。waitable 是包含平台句柄 union、`user_data`、`registered_waitset`、事件位和触发模式的 struct；平台初始化入口或调用方负责填平台句柄，waitset add/remove 维护注册状态。

4. Windows 64 wait-handle 上限在 P5b 追加时有明确错误映射；
