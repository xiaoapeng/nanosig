# Implementation Plan: nanosig 测试代码质量改进

> 基于 2026-05 测试代码审查报告实施
> 执行窗口：2026-06-28
> 状态：**已完成**

## 背景

2026-05 测试代码审查（详见 `docs/audit/`）识别出测试套件存在结构性问题和覆盖缺口。本计划将这些改进项分为三个优先级实施。

---

## 优先级矩阵

| 优先级 | 建议 | 工作量 | 影响 |
|--------|------|--------|------|
| 🔴 P0 | 提取线程抽象层 + 补充高危 API 缺口测试 | 小 | 消除大量重复，覆盖关键风险 |
| 🟡 P1 | 拆分 test_broker.c + 集成测试独立 + 统一宏 | 中 | 提高可维护性和诊断能力 |
| 🟢 P2 | 数据结构测试风格统一 | 小 | 一致性 |
| 🔵 P3 | EXPECT_EQ 增强 + gcov/lcov 覆盖率 | 小-中 | 更好诊断和覆盖分析 |

## P0：高危修复（urgency）

### P0-1：提取 test_thread.h 抽象层

**问题**：6+ 种不同变体的线程启动/等待/join 代码（`broker_loop_ctx_t`、`cross_thread_ctx_t`、`loop_thread_ctx_t`、`multi_loop_ctx_t` 等）散布在 broker/signal/loop/mpsc 测试中，核心模式完全相同。

**决策**：创建 `test/test_thread.h` — 跨平台 header-only 线程抽象。

```c
// 使用方式
static int my_worker(void *arg) { ... }
test_thread_t t;
test_thread_init(&t, my_worker, &my_state);
EXPECT_OK(test_thread_start(&t));
EXPECT_OK(test_thread_wait_ready(&t));
// ... 主线程操作 ...
test_thread_join(&t);
```

**产物**：
- `test/test_thread.h`（178 行）

### P0-2：补齐高危 API 缺口测试

**问题**：报告 §2.1 表格列出 10 个 API 行为缺失测试，其中 5 个被标记为高优先级。

**决策**：为每个高危缺口创建独立测试文件，单一关注点。

| 文件 | 覆盖缺口 | 行数 |
|------|---------|------|
| `test_signal_null_slot.c` | slot_fn == NULL 段错误风险 | 44 |
| `test_signal_double_deinit.c` | double-deinit 未定义行为 | 38 |
| `test_loop_reuse.c` | loop 复用状态残留 | 41 |
| `test_timer_deinit_use.c` | 计时器销毁后悬空指针 | 38 |
| `test_broker_concurrent_remove.c` | dispatch 中并发 remove | 70 |

**验证**：5 个测试全部在 ctest 中注册并通过，零回归。

## P1：结构性重构（maintainability）

### P1-1：拆分 test_broker.c

**问题**：`test_broker.c` 1854 行/60KB — 单个文件覆盖 broker 生命周期、事件投递、consume_fn、混合 watcher 等多个完全不同的测试域。

**决策**：按关注点拆分为 4 个独立文件，每个有自己的 `main()`。

| 新文件 | 行数 | 覆盖域 |
|--------|------|--------|
| `test_broker_lifecycle.c` | 430 | 生命周期、add/remove、无效路径 |
| `test_broker_event.c` | 564 | edge/level triggered、OUT/ERR 事件 |
| `test_broker_consume_fn.c` | 1035 | consume_fn 全部变体 |
| `test_broker_multi.c` | 344 | 多 watcher、混合 watcher |

### P1-2：应用 test_thread.h 统一线程抽象

**问题**：P0-1 创建的 `test_thread.h` 未被现有测试文件使用。

**决策**：将 11 个测试文件（4 broker 拆分 + 3 原始 unit + 4 integration scenarios）中的手动线程创建/join 替换为 `test_thread_t` API。

**结果**：消除约 350 行重复 boilerplate。9 个 integration scenario 因使用 `integration_create_loop()` 或 `ns_loop_start()` 管理线程，无需改动。

### P1-3：统一 test_platform_backend.c 宏

**问题**：`test_platform_backend.c` 是唯一未使用共享 `test_macros.h` 的主要测试文件，定义了独立的 `expect_ok()` 和 `expect_true()`。

**决策**：替换 179 处调用点 → `EXPECT_OK` 宏，删除本地定义。

**结果**：0 error 0 warning，风格统一。

### P1-4：集成测试独立编译单元

**问题**：集成测试 scenario 文件通过 `#include` 嵌入到 layer 入口文件，无法独立运行单个 scenario。

**决策**：为所有 14 个 scenario 文件添加 `#ifdef SCENARIO_MAIN` 门控 main()。在 CMakeLists.txt 中注册单独 target。

```c
// 每个 scenario 文件末尾
#ifdef SCENARIO_MAIN
int main(void) { return scenario_xxx(); }
#endif
```

**结果**：
- 独立运行：`ctest -R scenario_cascade`
- 合集运行：`ctest -R integration_layer`（layer 入口不变）
- 新增 14 个独立 target，layer 入口 4 个保持不变

## P2：一致性改进（consistency）

### P2-1：数据结构测试风格统一

**问题**：`test_ds_list.c`、`test_ds_slist.c`、`test_ds_ringbuf.c` 所有测试代码在单 `main()` 中。`test_ds_rbtree.c` 已采用分离式结构（`test_basic_ops()` + `test_invalid_inputs()` + `main()`）。

**决策**：将 3 个文件重构为与 rbtree 一致的分离式结构。

**结果**：3/3 测试通过，逻辑零修改。

### P2-2：Windows pipe 替代方案（暂缓）

**问题**：多个测试用 `#if !defined(_WIN32)` 跳过 socketpair/pipe 测试，Windows 覆盖率低。

**决策**：暂缓实施。需使用 Windows Named Pipe 或 `CreatePipe()` 实现等价替代。

## P3：能力增强（capability）

### P3-1：EXPECT_EQ 增强（非致命断言）

**问题**：现有 `EXPECT_OK`/`EXPECT_EQ` 在第一次失败时 `return 1`，丢失后续断言。

**决策**：在 `test_macros.h` 中添加 `EXPECT_OK_CONT` 和 `EXPECT_EQ_CONT` 变体。

```c
#define EXPECT_OK_CONT(expr, err_count)
#define EXPECT_EQ_CONT(a, b, err_count)
```

- 接收 `err_count` 参数，失败时递增而非返回
- 测试函数在最后 `return err_count > 0`
- 现有 EXPECT_OK/EXPECT_EQ 完全不变

### P3-2：gcov/lcov 覆盖率

**问题**：无法精准量化测试覆盖率。

**决策**：
1. 创建 `cmake/Coverage.cmake`（遵循 Sanitizers.cmake 模式）
2. 添加 `linux-coverage` CMake preset
3. 添加 coverage 自定义 target（lcov + genhtml）

```bash
cmake --preset linux-coverage
cmake --build --preset linux-coverage
ctest --preset linux-coverage -E stress
cmake --build build-coverage --target coverage
```

**结果**：
- 行覆盖率：**92.1%**（1449/1573）
- 函数覆盖率：**97.8%**（178/182）
- 报告：`build-coverage/coverage_report/index.html`
